# Feature coverage

This map is the completeness checklist for the v1 documentation. A
machine-readable `coverage-manifest.json` records all current package exports
and the first controller/event/error catalogs. Entries remain `partial` until
a capability has both a complete guide and a normative reference; the
manifest is a progress tracker, not a word-occurrence score.

“Live” means the page embeds the real controller and React adapter through
`StagesDemo`. Each live proof includes its exact, commented, copyable source
and the common field-adapter source; the documentation gate verifies those
source regions.

Low-level pure helpers are demonstrated by executable snippets and the linked
repository tests rather than browser controls. They have no UI behavior to make
interactive. The release gate verifies this page list and every live demo name
so additions cannot silently disappear.

`npm run check:docs:v1` derives runtime and type exports from all four package
entry points and compares them with the manifest. It also extracts diagnostic,
serialization-error, and collection-rejection codes from source; checks exact
snapshot, validation, persistence, and serialized-metadata members; checks
all diagnostic members, severities, codes, and catalog columns; checks nested
React binding members; checks nested navigation routes; verifies displayed
regions against strict TypeScript fixtures; and rejects known obsolete API
names in normative pages.

The initial manifest freezes exports and recognized code/event catalogs. Later
vertical slices will turn the remaining `partial` entries into complete
per-symbol references and extend the manifest to every public interface member
and discriminated-union branch.
