# Portable authoring API

**For:** runtime integrators and authoring-tool maintainers.
**Prerequisites:** [load a portable form](/start/portable-forms).

## Root entry point

| Export | Contract |
| --- | --- |
| `PortableFormDefinition` | Immutable JSON envelope: `format: 'stages-portable-form'`, `formatVersion: 1`, resolved `form`, `defaultLocale`, localization `resources`, explicit `initialValue`, and exact `requirements`. `form` retains the project-v1 node vocabulary, runtime identity, title, roots, rules, events and optional theme settings, but has no scenarios or fragment nodes. Legacy node metadata is excluded. |
| `PortableRequirements` | `capabilities` is exactly `['stages.standard@1']`. `services` contains unique key/version references sorted by key then numeric version; it must exactly match all service rules. Extra, missing, or reordered references fail validation. |
| `PortableDiagnostic` | Document/compiler diagnostic with `code`, `severity`, `source`, `message`, optional form/entity identity and property/runtime location. Existing `document.*` and `compiler.*` codes remain meaningful. |
| `PortableResult<T>` | Discriminated result: `{ ok: true, value: T }` or `{ ok: false, diagnostics }`. Failure has no executable value. |
| `PortableLoadOptions` | Optional trusted `serviceBindings`, `fieldBindings`, and `behaviorBindings` registries. No source evaluator, module resolver, browser host or implicit preview mocks. |
| `LoadedPortableForm` | Shared compiler outputs `schema`, `schemaInput`, `fields`, `expandedForm`, `renderPlan`, `sourceMap`, and `diagnostics`, plus immutable `definition` and `initialValue`. Use `schemaInput` for execution; `schema` alone omits dynamic structure. |
| `validatePortableForm(input: unknown)` | Checks JSON safety, envelope version/shape, graph references, field versions, resource format and exact requirements. Returns a deep frozen copy. Does not resolve services or establish that every accepted authoring feature can execute. Custom descriptor shape and exact field/behavior requirements are checked before binding resolution. |
| `loadPortableForm(input: unknown, options?)` | Accepts parsed JSON or JSON text. Runs validation, resolves each service exactly once, then compiles with the shared compiler. Rejects cyclic/unsupported-scope computed values, row-dependent structural presence, invalid scopes and other compiler errors. Returns `PortableResult<LoadedPortableForm>`. Never invokes a service during load; trusted behavior configuration factories do run during load. |
| `projectPortableForm(project, formUid, initialValue?, options?)` | Validates the selected project form, expands its linked fragments, strips scenario answers, legacy metadata and non-theme settings, and copies only referenced localization messages. The graph is bounded before expansion to 1,000 nodes. Missing/cyclic/parameterized fragments fail. Omitted `initialValue` uses empty built-in and custom field values; explicit JSON values, including null, are preserved. Projection checks compiler support with inert service placeholders; real bindings are required to load the artifact. |
| `serializePortableForm(definition)` | Serializes a typed definition with recursively sorted keys, two-space indentation and a final newline. Does not validate; validate untrusted data first. |
| `PortableServiceBinding` | Exact `key` and positive integer `version` matching the definition reference, with trusted `invoke({ input, validation })` returning a promise of success or structured failure. Cancellation and issue semantics follow core validation. |
| `PortableServiceBindings` | Registry with `resolve(reference)` returning an exact binding or undefined. A mismatched result fails loading. Host resolver exceptions propagate as application errors. |
| `definePortableServiceBindings(bindings)` | Creates an immutable exact-version registry and freezes bindings; duplicate key/version pairs throw `TypeError`. Implementations remain application-owned closures. |

## Values and extension contracts

| Export | Contract |
| --- | --- |
| `PortableValueContract` | Tagged JSON contract: string, finite number, boolean, null, enum, array, object or nullable. Objects have exactly their declared properties, all required. Nested descriptor contracts are limited to 32 levels; descriptor arrays have a 1,000,000-byte JSON-safety limit. Enum equality compares JSON structurally, ignoring object key order. This does not narrow core's rich-value model. |
| `PortableFieldDescriptor` | Namespaced key and positive safe-integer version, display name, value contract, explicit `emptyValue`, props contracts and `defaultProps`, draft/parsing/formatting expectations and accessibility metadata. Descriptors contain no executable code or framework exports. Defaults must satisfy their contracts. Every descriptor must be referenced by a field. Multiple exact versions may coexist. |
| `PortableFieldBinding`, `PortableFieldBindings`, `definePortableFieldBindings` | Trusted reducer and field validators with exact key/version; no view or initial-value override. The helper rejects duplicate references. A semantic reducer's returned accepted value must match the descriptor or core reports the thrown reducer failure. Explicit owner updates are not decoded. No implicit reducer accepts arbitrary drafts. |
| `portableFieldToken(reference)` | Returns `key@version`, used as the custom runtime field type and view token. Field-local declarative reducers may specialize the type while retaining this view token. |
| `matchesPortableValue(contract, value)` | Boolean shape check against a trusted descriptor contract; does not transform, execute business rules, enforce money precision, or establish server acceptance. |
| `PortableViewFields<TView>`, `PortableViewForm<TView>`, `bindPortableViews(loaded, views)` | Returns a loaded form whose schema and field types agree on the new view type. The frozen field registry contains host views and the same semantic callback references. Requires an own map entry for every field's view token; missing entries throw. Does not mutate schema, render plan, definitions, values or the original field registry. Components own accessible labels, descriptions, errors, focus/blur and draft parsing. |
| `PortableBehaviorReference` | Namespaced exact key/version with JSON-object config. References are unique and ordered; the requirements list must match that order exactly. |
| `PortableBehaviorBinding`, `PortableBehaviorBindings`, `definePortableBehaviorBindings` | Trusted `configure(config)` factory returns root core validators/transforms. Duplicate registrations throw. Loader checks exact versions; missing bindings, invalid configuration and duplicate validator IDs fail with diagnostics. Configuration factories must not perform request validation or start background work. Returned rules use core scheduling, dependencies, cancellation and validation issues. |
| `PortableProjectOptions` | Optional `fieldDescriptors` and ordered `behaviors` for projection. Only referenced descriptors are exported. Projection uses inert semantic bindings to check compiler support; production load still requires real bindings. Behavior factories are not executed during projection. |
| `PortableComposition`, `composePortableForm(loaded, composition)` | Adds trusted root validators/transforms after portable and referenced behavior rules. Requires a nonblank schema ID different from the source and a positive safe-integer version. Returns a new loaded output with the new runtime identity; retains the immutable source definition, render plan, fields and initial value. Duplicate validator IDs throw; transforms append in order. Dynamic structural factories remain dynamic. Compose once per deployment, not per render. |

`PortableFormDefinition` optionally includes `fieldDescriptors` and `behaviors`.
Requirements include `fields` only for custom descriptors, sorted by key and
numeric version, and `behaviors` only for referenced behavior. Absent optional
members preserve the S1 envelope and deterministic contact fixture byte for byte.
`validatePortableForm` does not resolve or execute any bindings. The loader
resolves semantics, checks compiler diagnostics and configures behavior before
returning a usable value. View bindings are never server requirements.

Failures added in this slice are `portable.invalid-field-descriptor`,
`portable.unused-field-descriptor`, `portable.missing-field-binding`,
`portable.invalid-behavior-reference`, `portable.missing-behavior-binding`, and
`portable.behavior-composition`. Existing requirements mismatch and compiler prop
diagnostics cover forged requirements and mismatched custom props. Custom fields
use exact versions in their runtime type; changing semantic bindings invalidates
Studio's compilation cache. Replacing a view map does not invalidate compilation.
The `/studio` compiler accepts `customFields` from `resolvePortableFields`;
`createEmptyStudioScenarioValue` accepts them as its third argument.

Callbacks in host composition are intentionally not serialized. Deployments must
record their implementation/configuration and compatibility decision separately;
content identity and full persistence migration remain S5 work. JSON value
contracts here supply the shape checks used by authoritative submissions.

## Scoped composition and computed values

`PortableNodeComposition` is accepted by `PortableComposition.nodes` and the
objects returned by a behavior binding. Keys are document UIDs; blocks, stages,
variants and unknown targets are rejected. `validators` and `transforms` append
to that node's rules. Duplicate validator IDs fail per scope, including repeated
binding composition. Field-only `deriveProps` merges after declarative derived
props. Additional `when` predicates combine by AND; `disabled` combines by OR.
Wizard-only `navigation` merges navigation settings; competing guards fail.
Collection variants are qualified by their source-map identity, so bindings do
not leak to another variant that shares a field path. Dynamic factories preserve
the same rules when a node reappears. Scoped transform contexts retain core's
event-target semantics, including `path`, rather than rebasing to the owner.

`PortableBehaviorBinding.configure(config, form?)` receives the approved form
from the loader/compiler. The optional second argument is additive to existing
factories. Studio forms may declare exact `behaviors` references. Projection moves
those references to the production envelope; explicit projection options override
the project references. Missing bindings fail Studio compilation with
`compiler.behavior-binding` and production loading with the existing portable
binding diagnostics. Invalid project references fail `document.invalid-behaviors`.
Studio compilation caches include binding-registry identity.

A field's `computed` expression supports `value`, current-parent `row`, and trusted
`context` scopes. Dependencies on computed fields are ordered conservatively by
path, including row templates; cycles fail with `compiler.computed-cycle` and
unsupported scopes with `compiler.computed-scope`. Both identify the computed
property. Expressions retain the existing bounded interpreter and value contracts.
Each row occurrence is evaluated independently; missing occurrences are skipped.
Computed results compare by JSON value, including structured custom values,
rather than by object identity.
Errors or invalid result shapes reject the entire event proposal through core's
transform-failure contract. No partial computed changes are accepted.

Computed transforms run after declared and composed transforms for input, blur,
submit, `recompute`, collection add/remove/replace/move/sort/duplicate, and events
listed by the form's named events, declarative reducers or transforms. Host-only
custom event names must be declared or followed by `recompute`. Computation does
not run implicitly on owner updates, context updates, restoration, or validate.
Validation instead recomputes expected values and reports `computed.mismatch` for
inconsistencies; expression failures make submission unavailable. Controller
proposal acceptance/rejection remains with the owner. The generated consistency
validator ID `portable.computed` is reserved within the form scope; collisions
fail with `compiler.computed-conflict`. Indexed value references to collection
computations are ordered before their consumers.

Property-keyed collection rows additionally require the declared key property as
a nonempty unique string. The decoder permits that property without a rendered
field and emits `submission.row-key` for missing, invalid or duplicate keys.
This is an additive acceptance contract for explicitly declared row identity;
all unrelated properties still fail decoding.

## Authoritative submissions

| Export | Contract |
| --- | --- |
| `PortableSubmissionDeployment` | Server-owned `definition`, nonblank immutable `revision`, and the same exact semantic/service binding options as the loader. The revision must cover artifact, binding implementations/configuration and acceptance policy. No client-supplied deployment is trusted. |
| `PortableSubmissionOptions` | Server-owned `context`, optional structural AbortSignal-compatible `signal`, and `timeoutMs` (default 10,000; finite positive number at most 2,147,483,647). No interaction state or extensions are accepted from the request. |
| `PortableSubmissionIdentity` | `revision`, `schemaId`, `schemaVersion` from the approved deployment, returned for every outcome. Revision assignment and registry lookup are host responsibilities; no automatic fingerprint is claimed. |
| `PortableSubmissionResult` | `accepted` includes identity, canonical JSON `value` and issues. `rejected` includes identity, `phase: 'decode' | 'validation'`, and issues. `unavailable` includes identity, empty issues and `reason: 'configuration' | 'execution' | 'timeout' | 'cancelled'`. Failed outcomes never expose a value. |
| `validatePortableSubmission(deployment, input, options?)` | Asynchronously validates a parsed unknown request value using the approved definition. Strict decoding precedes rule execution. Compiles a submission projection, creates fresh core state, awaits full submit validation and destroys that state in `finally`. No browser, renderer, Studio or framework is required. |

Submission inclusion is all declared values; unknown properties are rejected,
including nested custom objects and inactive-variant keys. Every declared key
must be present. Groups, wizards and stages each introduce their runtime ID as
an object segment; collection rows use only the selected discriminator variant.
Blocks introduce no data. Collections enforce their min/max and a hard maximum
of 1,000 rows each. Custom arrays are bounded by the total input budget.
Built-ins use their canonical primitive contracts; choices allow only trimmed,
nonempty newline-delimited options or the empty string. Dates, times and email
addresses remain strings: declare format/business validators. No draft parsing,
implicit defaults, trimming, event dispatch, reducer execution or transform
replay occurs. Null and empty values retain their explicit descriptor meaning.

All display `when`, `disabled`, and `presentWhen` behavior is removed for
submission validation. It cannot suppress required rules. Validator `when`
conditions remain authoritative business applicability and use core's normal
value/row/trusted-context semantics. Built-in, custom field, portable behavior,
and service validators all run through the existing core validation machinery.
Computed fields are checked for consistency; forged extra derived
properties fail decoding. Computed mismatches are reported as `computed.mismatch` with occurrence paths.

The transport reader rejects nonfinite numbers, nonplain objects, cycles,
accessors, symbol keys, unsafe keys, sparse arrays and nonenumerable properties.
It owns a JSON copy and limits work to 10,000 values, depth 64 and a conservative
1,000,000-byte estimate (six bytes per string/key code unit, plus overhead).
Decode issues use core `ValidationIssue` shape and occurrence paths, capped at
100 shape issues. Codes are `submission.non-json`, `submission.limit`,
`submission.object`, `submission.missing`, `submission.type`, `submission.choice`,
`submission.array`, `submission.collection-size`, `submission.discriminator`, and
`submission.unknown-property`. Business issues preserve rule IDs, paths,
localization and severities. Validation exceptions become unavailable execution,
not normal business rejection; missing bindings are unavailable configuration.

Service exceptions and malformed outcomes are unavailable execution; explicit
service failure is rejection even with warning severity. Ordinary non-service
warnings remain acceptable. Pending or unknown results never accept. Cancellation
is checked before work and before acceptance; the deadline covers elapsed setup
and validation time. Timeout/cancellation destroys the controller and signals
pending validators. Host services must cooperate to stop external work. Timers
cannot preempt synchronous regex or host callbacks; use deployment review and
process isolation for synchronous resource limits (the broader S5 gate remains
open). Accepted output is the decoded copy, with no UI proposals accepted.

## Format and failure behavior

`@stages/authoring/portable.schema.json` publishes a generated JSON Schema
2020-12 structural contract. Always run semantic validation and loading too:
JSON Schema does not prove graph references, cycle absence, execution scope or
host binding availability. Format version 1 is the first portable format; no
other portable versions are accepted. Existing Studio project-v0/v1 migration
remains available through the shared authoring surface. This does not change
core's serialized-state envelope or provide automatic runtime-state migrations.

The standard revision includes the existing built-in field catalog and bounded
expression language, ordinary required/length/range/pattern/comparison/collection
rules, conditional validation, transforms/reducers and localization. Unsupported
fields or definition versions fail. Resources support localization only; custom
portable codecs and fragment parameters are not supported.
The runtime value contract remains core's UI contract. An `initialValue` being
JSON-safe does not mean it passes a submission schema or business validation.

Portable failures use `portable.invalid-format`, `portable.unsupported-version`,
`portable.unknown-property`, `portable.missing-initial-value`, `portable.scenarios`,
`portable.unresolved-graph`, `portable.unsupported-resource`,
`portable.requirements-mismatch`, `portable.missing-service-binding`,
`portable.size-limit`, `portable.invalid-json`, `portable.missing-form`, and
`portable.fragment-expansion`. Messages explain the failed property or required
binding. JSON/document and compiler failures retain their existing codes and
source paths; document paths are expressed through the validated form graph.
No controller is created on failure. Successful loading does not mutate the
caller's data, accept proposals, start async validation, or retain controller state.

## Shared Studio authoring surface

`@stages/authoring/studio` is the extracted project-v1 authoring surface. It keeps
Studio-prefixed declarations so the existing editor, fixtures and migration
callers retain source compatibility. It exports the shared document validator,
serializer, migrations and UID utilities; expression declarations, evaluation and
validation; built-in field/presentation catalogs and trusted binding helpers;
localization; compiler outputs, source-map utilities, rule and transform compilers.
These functions retain their pre-extraction signatures and behavior. The emitted
API report inventories this compatibility surface. Studio-specific commands,
history, scenarios used as service mocks, editor state, and preview lifecycle
remain in Studio; none is required by production loading.

This lower-level compiler assumes validated authoring input. It may return a
partial graph with error diagnostics for editor recovery. Production consumers
should use the root loader, which refuses such graphs. The `renderPlan` does not
supply view components. Changing views does not change the compiler's runtime
identity, which remains the form's explicit schema ID and numeric version.
Definitions do not yet carry deployment fingerprints; maintain deployment
revision identity in the application until the durable-release slice.

## Durable release and state contract

`PortableRelease` is an additive `stages-portable-release` version-1 envelope.
Existing `PortableFormDefinition` version-1 JSON is unchanged. Its separate
`compiler` compatibility token is currently
`stages.authoring@1.0.0-alpha.0/standard@1`; other tokens fail explicitly.
`id` is SHA-256 of canonical sorted JSON for every envelope property except `id`.
It covers definition, host `bindingId`, host `policyId`, predecessor and decision.
Host IDs must be nonempty, at most 512 characters, and immutable for their contents.
The library cannot fingerprint callback source, closures, external services, or
host policy automatically. Updating those requires a new host identity.

`createPortableRelease(definition, options)` asynchronously returns deeply frozen
JSON. Options require binding/policy IDs; subsequent releases also require
`previous` and `compatibility: { changes, state, rationale }`. `changes` must match
`comparePortableReleases(previous, next)` exactly. Classification is conservative:
node identity/kind/links, field definitions and value descriptors are shape;
validators, reducers, computed expressions, props, defaults and policy are behavior;
node presentation, title/theme and localization are presentation; requirements
and host implementation identity are bindings. Categories may overlap. Schema ID
must remain stable within a lineage; versions cannot regress. Shape changes require
a higher schema version and `migrate` or `reset`, never `compatible`.

`loadPortableRelease(release, { bindingId, policyId, ...bindings })` verifies the
supported envelope/compiler, hash, definition and exact host identities before
loading. It snapshots caller data before awaiting the digest. It returns a
`LoadedPortableRelease`, which adds the immutable `release` to `LoadedPortableForm`.
`createPortableReleaseCache(capacity = 16)` returns an owner-created
`PortableReleaseCache` with `load` and `clear`. Capacity is an integer from 1 to 64;
overflow evicts the least-recently-used entry. Every load verifies content integrity
and exact host IDs before lookup. Standard forms reuse compiled definitions keyed
by release identity, returning detached schemas, fields, render plans and source
maps. Dynamic schema factory results are detached too. Definitions and release JSON
remain deeply immutable. No controller or request state is cached. Definitions
with field, behavior or service bindings compile freshly on every load: arbitrary
host closures cannot safely be reused across requests. `clear()` removes completed
cache entries; concurrent in-flight loads can subsequently populate the cache.
There is no global library cache. The host may cache approved frozen release JSON
by content identity as well.
`serializePortableRelease` sorts keys with a trailing newline; it does not validate.
These APIs require Web Crypto (available in supported browsers and Node 24).
Failures throw `TypeError` with `portable.release-*` prefixes; they never publish,
execute a service, or overwrite a previous release. Successful preparation is not
a claim that a deployment passed installed consumers or manual product gates.

`savePortableState(loaded, controller.serialize())` returns frozen
`PortableSavedState`: `{ format: 'stages-portable-state', formatVersion: 1,
releaseId, state }`. It checks the core envelope/schema against the release and
retains baseline plus all metadata. It cannot prove that a caller-provided state
came from that controller, or that values pass business rules.

`migratePortableState(saved, target, migrations?)` returns a new saved envelope.
Each `PortableStateMigration` supplies verified `from`/`to` releases, a complete
core-envelope callback, baseline policy, and per-key metadata policies. Exactly
one outgoing transition must match at each step; `to.previous` must match `from.id`.
The chain stops only at the target release; cycles and chains over 100 steps fail.
A target declaring reset cannot consume an old state through migration.
Callbacks receive independent copies twice; output must be deterministic, JSON-safe
and match the destination schema. `baseline: preserve` checks exact equality;
`reset` checks equality to output value; `migrate` accepts an explicitly transformed
baseline. Metadata `preserve` checks equality, `reset` requires omission, and
`migrate` allows a changed key. Every source or destination key needs a policy,
including collectionKeys, activeWizards, touched, visited, revealedValidation and
extensions. Policies apply at the top-level metadata key; a host migrating
extensions owns the policies for each nested extension. Unknown keys never disappear
implicitly. Callback failures propagate; contract failures use `portable.state-*`
TypeErrors. Input remains untouched. Recreate a controller with the returned core
state and the target fields/codecs to check runtime metadata and value decoding.
Neither migration nor restoration replaces authoritative submission validation.

Fragment expansion now applies the same total 1,000-node allocation limit to
Studio preview and production export. Preview reports
`compiler.fragment-expansion-limit` and an empty graph on overflow; export retains
its existing `portable.fragment-expansion` diagnostic. Per-document and expression
budgets still apply. Native pattern execution cannot be interrupted by an in-process
timer: server deployments requiring hard synchronous deadlines use the tested
worker hosting recipe. It retains existing pattern semantics rather than silently
weakening validation.
