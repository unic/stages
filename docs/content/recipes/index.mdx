# Real-world recipes

**For:** Application teams composing Stages capabilities into production
workflows.

**Prerequisites:** A working [controlled controller](/core-concepts/controlled-values)
and the guide for each capability used by the recipe.

These recipes start where focused feature guides stop. Each one assigns work
to core, an adapter, or application infrastructure; shows a checked production
pattern; and makes concurrency, failure, accessibility, testing, and teardown
policy explicit.

## Ownership rule

Stages owns deterministic schema evaluation, proposals, validation state,
collection commands, wizard metadata, snapshots, and serialization. The
application owns I/O, accepted-value policy, request cancellation, storage,
routing, history, localized catalogs, telemetry transport, and process or UI
lifecycle. Adapters own markup, focus mechanics, and accessible field views.

The boundary is intentional: core never starts a fetch, writes storage,
changes a URL, or retains an undo stack. Those operations need product policy
and lifecycle coordination that a form engine cannot infer.
