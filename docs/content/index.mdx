# Stages v1

Stages is a framework-neutral, controlled engine for forms, collections, and
wizards. The core owns schema evaluation, immutable value proposals,
validation, navigation, and serializable interaction state. Your application
owns the accepted value, markup, field components, and visual design.

<Callout emoji="🧪">
  The v1 packages are currently published from this repository as an alpha
  candidate. Their contracts are implemented and release-gated, but the stable
  1.0 package has not been published yet. See the
  [release status](/project/release-status).
</Callout>

## Packages

- `@stages/core` — dependency-free controller, schema, events, validation,
  collections, transforms, paths, and serialization.
- `@stages/dom` — a small accessible native-DOM reference adapter.
- `@stages/react` — React lifecycle, field, collection, and wizard bindings.
- `@stages/test-kit` — reusable adapter contract tests.

## Why Stages?

- One recursive schema models fields, groups, collections, and wizard stages.
- Controlled ownership makes every accepted domain-value change explicit.
- Field views are opaque tokens to the core, avoiding framework lock-in.
- Dynamic visibility and disabled state are derived without mutating schemas.
- Validation supports event policies, reveal policies, dependencies,
  cancellation, and scoped aggregation.
- Stable row addresses preserve interaction state through collection moves.
- Serialization supports migrations, custom value codecs, and extension state.

## Find the right level of detail

- **Start here** teaches a working controller in dependency order.
- **Core concepts** explains ownership and lifecycle decisions.
- **Feature guides** cover schemas, validation, structures, persistence, and adapters.
- **API reference** inventories the exact implemented package surface.
- **Project** records architecture boundaries, measured budgets, and release maturity.

Every new normative page states its audience, prerequisites, next step, and
source/test evidence. The [feature coverage page](/feature-coverage) explains
how the machine-readable inventory prevents new exports from bypassing docs.
