# Persistence, codecs, and migrations

`controller.serialize()` returns a JSON-safe `SerializedStagesState` envelope:

<StagesDemo example="persistence" />

The envelope records format/version, schema ID/version, canonical value,
initial baseline, and durable metadata: touched/visited nodes, revealed issue
addresses, active wizard stages, collection row keys, and registered extension
namespaces. It intentionally excludes focus, listeners, validation results, and
pending async work.

Recreate instead of mutating an old controller:

```ts
const state = controller.serialize();
controller.destroy();

const restored = stages({
  schema,
  fields,
  state,
  migrations,
  codec,
  extensionCodecs,
});
```

## Strict JSON boundary

`encodeJson` rejects `undefined`, functions, symbols, bigint, non-finite
numbers, cycles, non-plain objects, and unsafe keys. It throws
`SerializationError` with stable `code` and precise `path`. `decodeJson`
recreates safe arrays and plain objects. `validateSerializedState` validates an
untrusted envelope before use.

For dates or other rich domain values, provide a `StagesValueCodec<TValue>`
whose `encode` returns JSON and `decode` reconstructs the domain value.

## Extension state

Extensions are namespaced metadata supplied through `extensions`. Every
persisted namespace must have a registered `{ encode, decode }` codec. Unknown,
unsafe, or failing namespaces are rejected rather than silently dropped.

## Ordered migrations

A `StagesStateMigration` declares `schemaId`, `fromVersion`, `toVersion`, and
`migrate(state)`. Versions must strictly increase and each starting version may
have only one migration. `migrateSerializedState` follows the chain, validates
every output, and rejects cycles, ambiguity, wrong identities, and failures.
Migrations update both serialized `value` and `baseline` before recreation.
