# Controller and snapshots

`stages(options)` creates one isolated, framework-neutral controller. It accepts
either a controlled `value` for a new instance or serialized `state` for
recreation—never both.

## Controlled ownership

Reducers, transforms, and collection commands produce a proposed value. Core
calls `onChange` but does not adopt that proposal. The owner may accept it with
`update({ value: change.value })`, replace it, delay it, or reject it. This makes
server synchronization, undo stacks, optimistic UI, and policy enforcement
possible without special modes.

## Controller methods

| Method | Contract |
| --- | --- |
| `getSnapshot()` | Returns the current immutable value, render tree, validation, revision, and diagnostics. |
| `subscribe(listener)` | Runs after a published controller change; returns an unsubscribe function. |
| `subscribeSelector(selector, listener, isEqual?)` | Runs only when the selected result changes. General listeners run first. |
| `update(input)` | Replaces controlled `value`, `context`, `schema`, or registered `extensions`. |
| `dispatch(event)` | Sends one named field, node, or form event. Events in one turn share a transaction. |
| `batch(run)` | Explicitly groups all dispatches in `run` into one proposal and notification. |
| `validate(options?)` | Runs form-, path-, or address-scoped validation and resolves to its snapshot. |
| `serialize()` | Produces a validated JSON-safe state envelope. |
| `destroy()` | Cancels validation, clears subscriptions, and makes later work inert. |

## Snapshot anatomy

`StagesSnapshot<TValue>` contains `value`, monotonically increasing `revision`,
recursive `nodes`, aggregate `validation`, and `diagnostics`. Field snapshots
add their resolved `view`, `props`, `value`, `initialValue`, `path`, `address`,
and interaction state. Container snapshots add collection size/capabilities,
wizard navigation, stage activity, or row branches as appropriate.

Snapshots are readonly and structurally share unchanged branches. Never mutate
them. A narrow adapter should select the smallest stable branch with
`subscribeSelector`; pass a custom equality function only when reference
equality is not the desired contract.

## Change records and ordering

`onChange` receives `value`, `previousValue`, ordered `patches`, source
`events`, `source`, and `transactionId`. Synchronous acceptance inside
`onChange` is included in the same publication. Delayed acceptance publishes
the unchanged canonical snapshot first, then publishes again when `update`
accepts a value.

Each controller owns its transactions, metadata, subscriptions, cancellation,
and row keys independently. There is no global form state.
